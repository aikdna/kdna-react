# React remote Read consumption contract

The runtime imports React and the root public Web Client only. The caller owns endpoint/session configuration and a fresh ReadTransportContext. Web Client owns local selection admission, Read transport admission and ClientResult; React owns effect/resource lifetime and presentation. There is no fileId upload service, inspect-to-LoadPlan-to-load path, Runtime Capsule, password/license/activation API, raw manifest/payload parser, local Validator/JCS/closure/resolver or server fallback. Old import names and deep package paths fail closed.

Only an explicit read sends selected bytes. Input replacement cancels outstanding reads and releases the previous selection, even when earlier selection processing completes late. Reads can overlap within the configured client limit; the latest-started read controls visible result, and all returned promises retain their actual result. An operation superseded during selection returns REACT_SELECTION_SUPERSEDED and its acquired selection is released. Cancel preserves the current selection; release clears it; dispose remains final until a fresh option/effect instance. Unmount owns cleanup and suppresses late state changes. Stable primitive options and fetch identity avoid unnecessary effect replacement.

The state phase is a UI lifecycle, not a new public protocol status. Received ClientResult can describe an admitted ready envelope, denied response, no-body control or remote transport failure. KDNAReadStatus projects those to received/denied/no-body/failed; rejected/failed client results retain their real code. KDNAReadView only renders public disclosed content and proof limits as bounded text. Missing disclosure is explicit. There is no expand button: positive cross-request expansion is NOT_PROVEN. False authorization/action capabilities are never upgraded.

The optional `selectionResult` field stores the exact public result of the current selection attempt. Replacement, release, disposal and effect replacement clear it; cancellation retains the current attempt together with any still-selected file. This field does not authorize a read. Current component rejection details are displayed transparently, without a local schema, method interpreter or permission decision.

Use `KDNAReadView({state: reader})` for phase-aware presentation. The supplied state owns its result, even if a separate result prop is also supplied. With no result, only observable local lifecycle information is stated. The legacy result-only form remains available with its generic no-response instruction. Neither form invents content existence, a service cause, a role capability or a recovery action from missing disclosure.

The package is source JavaScript; scripts/check.cjs verifies syntax and the exact public runtime surface. Strict declaration checks use the locked local TypeScript 5.9.3 dependency by default; `KDNA_TSC_JS` is an explicit tool override for isolated verification. `npm test` uses React 18.3.1 and in-process Request/Response fixtures with the current public Core and Read. It opens no listener and does not establish real HTTP, browser layout, CORS, remote identity or a remote acknowledgement. The separate historical `npm run test:http` requires its real Host fixture and `KDNA_TEST_ORIGIN`; this candidate does not claim that historical fixture was rerun. Tests and dev drivers are excluded from the package. Protected repository vendor and audit history is not distribution content or current authority.
